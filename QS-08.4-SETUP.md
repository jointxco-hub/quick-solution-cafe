# QS-08.4 — resilient PayFast return flow

This patch finishes the customer-facing payment return/recovery experience.

## What it changes

- stores the payment token locally against the exact Quick Solution order,
- redirects to PayFast in the **same tab**,
- recognises `?qs_payment=return&order=...` and `?qs_payment=cancel&order=...`,
- polls the server-side payment status after PayFast returns,
- never trusts the return URL itself as proof of payment,
- shows a proper `Paid / Confirming / Not completed` Quick Solution screen,
- keeps a manual **Check payment again** fallback,
- repairs any remaining `Â· / â€“ / â€¦` text corruption from the earlier Windows PowerShell patch.

The actual paid state still comes only from the validated PayFast ITN.

## Apply

Copy this patch into the Quick-Solution-Cafe repo, then from the project root:

```powershell
node .\scripts\apply-qs084-return-flow.mjs
npm run dev
```

For local testing, keep Vite running while PayFast redirects back to `localhost:5173`.

## Acceptance

Create a new sandbox order, pay it, and let PayFast return in the same tab.

Expected:
1. Quick Solution return page opens instead of the normal storefront.
2. It displays **Checking payment** briefly.
3. Once the validated ITN lands, it becomes **Payment confirmed / Paid**.
4. Orders Admin stops showing `Payment pending`.
5. If the job was already sent to OPPS, OPPS payment state updates as well.
