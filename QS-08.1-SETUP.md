# QS-08.1 hotfix

The screenshots exposed two separate issues.

1. Payment initialization was calling commerce RPCs through the default `public` schema.
   XOS Staging has already been fixed and `quick-solution-payfast` is now version 3.

2. Windows PowerShell 5.1 read the UTF-8 source files as the system code page in the first
   QS-08 patch, which produced text such as `Â·` and `â€“`.
   This hotfix repairs those sequences using Node's explicit UTF-8 file handling.

## Apply locally

From the Quick-Solution-Cafe project root:

```powershell
node .\scripts\apply-qs081-hotfix.mjs
npm run dev
```

Refresh the confirmation for `QS-260913-F87E` and click **Pay securely with PayFast** again.
The existing payment token is still valid; you do not need to create another order.

Do not complete a real PayFast payment unless you intend to test the configured PayFast environment.
