# QS-09.1 — South African phone-number tracking fix

The secure tracking link was already working.

The manual lookup failure came from phone-number formatting:
- order stored: `+27671176230`
- customer typed: `0671176230`

Those are the same South African number, but QS-09 originally compared only stripped digits.

XOS Staging is already fixed with:

`20260913203520_qs_09_1_sa_phone_tracking_normalization`

Accepted equivalents now include:
- `0671176230`
- `+27671176230`
- `27671176230`
- `671176230`

Email matching is unchanged.

Wrong phone numbers still return the same generic empty result, so the privacy behavior remains intact.

## Apply source patch

Copy into the repo and run:

```powershell
node .\scripts\apply-qs091-phone-normalization.mjs
npm run dev
```

Then retry:

- Order: `QS-260913-56AC`
- Phone: `0671176230`

It should now load the same order shown by the secure tracking link.
